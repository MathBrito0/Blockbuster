### ![Seção](https://img.shields.io/badge/📖_Sobre_o_Projeto-1677FF?style=for-the-badge)

O **Blockbuster — Locadora Digital** é um projeto acadêmico desenvolvido para a disciplina de **Programação Web**, no curso de Bacharelado em Cibersegurança da **PUCPR**.

A proposta consiste em reproduzir digitalmente a experiência de uma locadora de filmes clássica, utilizando uma interface temática inspirada na identidade visual da Blockbuster e funcionalidades de uma aplicação web moderna.

Mais do que apresentar um catálogo cinematográfico, o projeto busca aplicar conceitos de desenvolvimento Full-Stack, comunicação cliente-servidor, persistência de dados, autenticação e segurança da informação.

## ![Seção](https://img.shields.io/badge/🏗️_Arquitetura_e_Implementação-FFD429?style=for-the-badge)

A aplicação utiliza uma arquitetura cliente-servidor, separando as responsabilidades de apresentação, processamento das requisições e armazenamento dos dados.

### Frontend

Responsável pela interface e interação com os usuários.

- HTML5 para estruturação das páginas.
- CSS3 para identidade visual e organização do catálogo.
- JavaScript para validações e interações dinâmicas.
- Fetch API para comunicação assíncrona com o backend.

### Backend

Desenvolvido em PHP, concentra as regras de negócio e o processamento das requisições.

- Gerenciamento de autenticação e sessões.
- Validação de permissões dos usuários.
- Processamento de cadastros.
- Endpoints para operações relacionadas aos filmes.
- Comunicação com o banco de dados utilizando PDO.

### Banco de Dados

O MySQL é responsável pela persistência das informações da aplicação.

As principais entidades utilizadas são:

- `usuarios`: armazenamento dos dados de cadastro, autenticação e perfil dos usuários.
- `filmes`: armazenamento das informações do catálogo cinematográfico.

## ![Seção](https://img.shields.io/badge/🔐_Segurança_da_Informação-1677FF?style=for-the-badge)

A segurança foi considerada um dos pilares do desenvolvimento, com a aplicação de mecanismos para proteger os dados dos usuários e restringir operações administrativas.

### 1. Proteção contra SQL Injection

As operações de banco de dados utilizam **Prepared Statements através do PDO**, separando os comandos SQL dos dados fornecidos pelos usuários.

### 2. Armazenamento Seguro de Senhas

As senhas não são armazenadas em texto puro.

O sistema utiliza `password_hash()` em conjunto com uma chave adicional denominada **PEPPER_KEY**, acrescentando uma camada de proteção ao processo de armazenamento das credenciais.

### 3. Proteção de Sessões

Após a autenticação bem-sucedida, o sistema executa `session_regenerate_id(true)`, renovando o identificador da sessão para reduzir riscos associados a ataques de Session Fixation.

O logout também realiza a destruição dos dados da sessão ativa.

### 4. Controle de Acesso — RBAC

O sistema implementa controle de acesso baseado em perfis (*Role-Based Access Control*).

| Perfil | Permissões |
|---|---|
| **Visitante** | Cadastro e acesso às funcionalidades públicas. |
| **Cliente** | Navegação pelo catálogo e consulta de filmes. |
| **Funcionário** | Acesso às funcionalidades de gerenciamento administrativo. |

As permissões são verificadas em duas camadas:

- **Frontend:** elementos administrativos são exibidos conforme o perfil do usuário.
- **Backend:** os endpoints verificam a sessão e as permissões antes de executar operações restritas.

Essa abordagem impede que a simples manipulação da interface seja suficiente para acessar funcionalidades administrativas.

## ![Seção](https://img.shields.io/badge/⚙️_Automação_Auto_Seed-FFD429?style=for-the-badge)


Para simplificar a configuração do ambiente e facilitar a apresentação do projeto em diferentes máquinas, foi implementado um mecanismo de **Auto-Seed**.

Durante a inicialização do sistema:

1. O backend verifica os e-mails dos integrantes previamente configurados.
2. Caso uma conta ainda não exista, um novo registro é criado.
3. As credenciais são armazenadas utilizando o mecanismo de Hash + Pepper.
4. As contas da equipe recebem automaticamente o perfil `funcionario`.

O processo também evita a duplicação de usuários já cadastrados.

### 🚀 Como Executar o Projeto

### Pré-requisitos

Antes de iniciar, certifique-se de possuir:

- [XAMPP](https://www.apachefriends.org/pt_br/index.html) instalado.
- PHP 8 ou superior.
- MySQL ou MariaDB.
- Navegador atualizado.
- Git (opcional).

### 1. Clonar o repositório

Abra o terminal e navegue até a pasta `htdocs` do XAMPP:

```bash
cd C:\xampp\htdocs
```

Clone o repositório:

```bash
git clone https://github.com/SEU-USUARIO/NOME-DO-REPOSITORIO.git
```

### 2. Iniciar o ambiente

Abra o painel de controle do XAMPP e inicie os serviços:

- Apache
- MySQL

### 3. Configurar o banco de dados

1. Acesse o phpMyAdmin:

   http://localhost/phpmyadmin

2. Importe o arquivo `banco.sql`, localizado na raiz do projeto.
3. Execute a importação para criar as tabelas e popular o catálogo inicial.


### 4. Configurar a conexão

Verifique o arquivo responsável pela conexão com o banco de dados e configure os parâmetros necessários:

| Parâmetro | Valor |
|---|---|
| Host | `localhost` |
| Banco de Dados | `blockbuster_db` |
| Usuário | `root` |
| Senha | Conforme configuração local do MySQL |

Configure também a variável `PEPPER_KEY`, caso seja exigida pelo sistema.


### 5. Acessar a aplicação

Com Apache e MySQL ativos, abra o navegador e acesse:

```text
http://localhost/NOME-DO-REPOSITORIO/
```

Após a inicialização, o sistema estará disponível para utilização.
